# 方案评审：图层 / 图形库 / 毫米坐标 / 画布预设

> 评审对象：用户提出的 GUI 设计器方案（2026-10-26）
> 结论：**方向都对，可以直接照着做**；但有 5 处需要在动手前定死，否则做出来的东西导不进插件运行时，
> 或者导进去了"设计器里看着对、插件里不对"。
>
> 本文档所有关于运行时的陈述都来自 `rustomp/crates/rustomp-gui/src/lib.rs` 的实际代码，
> 不是推测。

---

## 0. 方案原文（复述，便于对照）

1. 复用 breadspice 架构；
2. 采用 JSON 格式；
3. 每类图形元素分配一个图层（背景层、丝印层、开关层、旋钮层、LED 层），形成树状目录；
4. 内置基础 SVG 图形库（纯色背景、各种形状旋钮、拨杆开关、脚踏开关、常用丝印文字、LED），
   用户可自行导入 SVG 或 PNG；
5. 坐标以毫米为最小单位，各类图形元素**头部对齐到整数毫米**；
6. 提供 1590B 等常见画布尺寸预设，也可自定义。

## 1. 逐条评估

### 1.1 复用 breadspice 架构 —— ✅ 同意

与电路设计器（`rustomp-circuit-designer`）保持一致，两个设计器共享一套心智模型。

补充两点（GUI 设计器与电路设计器不同）：

| 点 | 说明 |
|---|---|
| **后端很薄** | 电路设计器要把网表变成代码；GUI 设计器只需要：读 `rustomp.toml` 的 `[[params]]`、栅格化 SVG/PNG、写回 `[assets]/[ui]`。所以后端只有"文件 + 渲染"两类接口，**不要**为它设计复杂的 RPC |
| **预览必须复刻运行时** | 预览不是"随便画一下"：它要复刻 `rustomp-gui::draw()` 的缩放/角度/基线规则（`02-runtime-panelspec.md` §6）。建议前端直接实现一份 TS 版 `draw()`，与 Rust 版**逐条对齐**（甚至可以把 5 条规则写成共享的常量表） |

### 1.2 JSON 格式 —— ✅ 同意，补 3 条约束

| 约束 | 原因 |
|---|---|
| 带 `version` 字段 | 将来加图层类型/控件类型时不至于读不了旧文件 |
| **键序稳定 + 数值不写浮点噪声**（`43.4` 不写 `43.400000000000006`） | 与 rustomp 的生成物一样要能 diff、能做漂移检查 |
| 设计稿与导出物**分离** | `.box.json`（设计态：参考图、网格、辅助线、素材内容）→ 导出 `rustomp.toml [ui]` + PNG。**导出幂等**：同一份设计永远导出同样的字节 |

### 1.3 图层方案 —— ✅ 方向对，**但"层"的划分依据要改**

原方案的五个层（背景/丝印/开关/旋钮/LED）是按**元素类别**分的，很直观。但运行时的绘制是
**固定顺序 + 部分压平**，所以"层"还必须承担一个职责：**说明这个层在导出时去哪**。

运行时的实际绘制顺序（代码里就是这样，不可配置）：

```text
1. 底色（background 填充整个可用区域）
2. 面板底图（panel PNG，铺满 rect）
3. LED 实心圆（颜色 = off→on 按 activity 插值）
4. 每个旋钮的指针线（颜色硬编码 0xf5f5f5，线宽 ≥2px）
5. 拨杆贴图（两态之一，按住时以 pivot 缩放）
6. 按钮：从**底图**里抠出 center±radius 的方块 → 原位置填底色 → 贴回缩小版
```

由此推出**每个层的最终去向**（这是方案里缺的最关键一块）：

| 层 | 导出时去哪 | 说明 |
|---|---|---|
| 背景层 | **压平进 panel.png** | |
| 丝印层 | **压平进 panel.png** | 文字/刻度/logo，运行时**不渲染文字** |
| 旋钮层 | **旋钮本体压平进 panel.png**；指针由运行时画 | 指针位置要留空，否则重影 |
| 开关层 | 拨杆的**活动部分**导出成独立 PNG（up/down 两张）；**底座/边框**压平进 panel.png | 活动部分要移动，不能压平 |
| LED 层 | **不进 panel.png**（由运行时画圆）；底图上只留"熄灭态"的底色/凹陷 | 运行时画实心圆，会盖住该区域 |
| 按钮（脚踏/bypass） | **必须压平进 panel.png**（运行时是从底图抠出来缩放的） | 这条最反直觉，见 §3.1 |
| 装饰层（新增建议） | 压平进 panel.png | 纯美术元素（螺丝、贴纸、做旧） |

**建议把"开关层"再拆成两半**，因为它们性质不同：

- **开关-装饰**（脚踏开关的外观、不绑定参数）→ 压平；
- **开关-控件**（拨杆，绑定 bool 参数）→ 导出两态 PNG + `[ui.toggle]`。

### 1.4 内置 SVG 图形库 —— ✅ 同意，建议沿用 GB4728 那套规范

你已经有一套很讲究的符号资产（`gb4728-symbols-kit`）：1 单位 = 1 mm、2.5 mm 栅格、线宽 0.45/0.9、
只 translate 不 scale。**面板图形库建议沿用同一套约定**：

| 项 | 建议 |
|---|---|
| 单位 | 1 SVG 单位 = 1 mm（与画布 mm 直接对应，不用换算） |
| 分组 | `knobs/` `toggles/` `footswitches/` `leds/` `texts/` `backgrounds/` |
| 每个图形带一行**机器可读注释**（名称/尺寸/锚点/可绑定参数类型） | 与符号集的做法一致，便于生成清单 |
| 只 translate 不 scale | 缩放会破坏"整数毫米对齐" |

用户导入 SVG/PNG 时的两个硬约束：

1. **PNG 必须保留 alpha**（否则拨杆边缘会发糙 —— legacy 实测过）；
2. **SVG 里的文字要么转路径、要么由设计器用自己的字体重排**（否则依赖系统字体，换机器就变样）。

### 1.5 毫米坐标 + 整数毫米对齐 —— ⚠️ **需要精确定义，否则会做错**

方向完全正确（**1 素材单位 = 1 mm**），而且能让 `svg_width/svg_height` 变成"真实物理尺寸"，
这是最好的选择。但有三处必须定义清楚：

**① "头部对齐"对齐的是哪个点？**
建议：每个元素有一个**锚点**（默认"顶部中心"，可切"左上/中心"），**锚点**吸附到整数 mm。
不要用"包围盒顶部"——旋钮旋转后包围盒会变。

**② 只有"位置"吸附整数 mm，尺寸必须保留 0.1 mm 精度**
legacy 的实际数据就是小数：`radius = 27.86`、`pointer_width = 0.98`、`pointer_len = 24.59`。
如果把尺寸也量化到 1 mm，指针线宽 0.98 → 1.0，视觉上就会变粗。
建议：**位置吸附 1 mm（按住 Alt 解除），尺寸保留 0.01 mm 输入精度**。

**③ 旋钮的"实质"是参数，不是像素**
`[ui.knobs]` 要的不只是圆心，还有 `radius`（命中半径）、`pointer_len`、`pointer_width`、
`angle_min/max`、`drag_full_range_px`。设计器必须**把这些当作可编辑属性**，
而不是只让用户贴一张旋钮图。否则导出的 `[ui]` 无法还原交互。

### 1.6 画布尺寸预设 —— ✅ 同意，注意"外尺寸 ≠ 面板尺寸"

常见外壳（**数值为标称值，务必以厂商图纸复核**；且面板要扣掉圆角与内衬边距）：

| 预设 | 外尺寸（约） | 面板可用（建议） | 备注 |
|---|---|---|---|
| 1590A | 92 × 39 mm | ~86 × 34 mm | 小块 |
| **1590B** | 112 × 60 mm | ~104 × 54 mm | 最常见 |
| 1590BB | 119 × 94 mm | ~110 × 86 mm | 双排布局 |
| 125B | 121 × 67 mm | ~113 × 60 mm | 常见于现代踏板 |

建议预设里同时存 **`outer_mm`（外壳外尺寸）** 与 **`canvas_mm`（可打印区域）**，
并在画布上画一圈"安全边距"辅助线（默认 4 mm）。

同时建议出两个**独立**的导出：

1. **插件素材**（panel.png @2x + 拨杆贴图）→ 给运行时；
2. **1:1 打印图**（PDF/SVG，mm 精确）→ 给做贴膜/丝印。
   这两者的用途不同，不要混在一起。

## 2. 方案没覆盖、但必须现在定的 5 件事

### 2.1 按钮（bypass/脚踏）的美术必须"压进底图"

运行时对按钮的处理是：**从 panel 贴图里抠出 `center ± radius` 的方块**，
把原位置填成底色，再把抠出来的方块缩放贴回。这意味着：

- 按钮的美术**必须在 panel.png 上**（不能在独立图层/独立 PNG）；
- 美术必须**以 `center` 为中心**，且落在 `radius` 的方形范围内（超出部分会被裁掉）；
- "按下"效果只是**缩放**，没有"按下态贴图"这个概念。

→ 设计器必须把"脚踏开关/按钮"层的元素**压平进底图**，并额外记录 `center`/`radius`/`press_scale`。

### 2.2 文字必须栅格化（运行时不渲染任何文字）

`PanelSpec` 里没有文字元素。所以**丝印层的所有文字都要在导出时进入 panel.png**。
推论：

- 设计器要自带字体（或让用户提供字体文件），并注意字体许可（商用面板要可再分发）；
- 字号/字距在**毫米**下定义（例如"3.5 mm 高的字"），这样换 DPI 不变；
- 导出后文字不可再编辑（在插件里）——这是可接受的，但要写清楚。

### 2.3 控件数量上限（当前运行时）

| 控件 | 上限 | 对设计器的影响 |
|---|---|---|
| 旋钮 | 不限 | 随便放 |
| LED | **1** | 设计器要在 UI 上拦住第 2 个，或标记为"导出会失败" |
| 拨杆 | **1** | 同上 |
| 按钮 | **1** | 同上 |

→ 建议：设计器**数据模型按"多个"设计**（数组），导出时按当前能力**校验并报错**；
同时把"扩展 `rustomp-gui` 为数组"排进 rustomp 的待办（见 §4）。

### 2.4 每个控件必须绑定参数 id

`[ui.*]` 的 `param` 必须指向插件 `[[params]]` 里真实存在的 id，否则运行时那个控件不动。
→ 设计器要能"打开一个插件项目"，读它的 `[[params]]`，把可绑定的 id 列出来给控件选；
**绑定不存在的 id 要在导出前报错**（和 rustomp 的"型号不在闭集表就报错"是同一个原则）。

### 2.5 指针颜色是**硬编码**的

运行时画旋钮指针用的是固定色 `0xf5f5f5`（近白）、线宽 `max(2px)`。
→ 面板底色如果也是浅色，指针会看不见。设计器在"预览"里要如实显示这一点
（或者把"指针颜色可配置"作为 `rustomp-gui` 的扩展项提出来）。

## 3. 建议的修订版规范（v0.2 草案）

### 3.1 图层（6 层，按"去哪里"划分）

```text
box.json
└── layers[]                       # 顺序 = 绘制顺序（自下而上）
    ├── background   背景层         → 压平进 panel.png
    ├── artwork      装饰层（新增）  → 压平（螺丝/贴纸/做旧/脚踏开关外观）
    ├── silkscreen   丝印层         → 压平（文字/刻度/logo，导出时栅格化）
    ├── knobs        旋钮层         → 本体压平；指针留空，运行时画
    ├── toggles      拨杆层         → 活动部分导出两张 PNG；底座压平
    └── leds         LED 层         → 不进底图（运行时画圆）；底图只留熄灭态
```

每层内部支持分组（树），分组只影响编辑，不影响导出。

### 3.2 `box.json` 草案（关键字段）

```jsonc
{
  "version": 1,
  "canvas": {
    "preset": "1590B",              // 或 "custom"
    "outer_mm": [112.0, 60.0],      // 外壳外尺寸（参考）
    "canvas_mm": [104.0, 54.0],     // 可打印区域 = 素材坐标（1 单位 = 1 mm）
    "safe_margin_mm": 4.0,
    "window_px": [312, 162]         // 初始窗口（= canvas_mm × 3）
  },
  "layers": [
    { "id": "bg",   "kind": "background", "elements": [ /* rect/raster/svg */ ] },
    { "id": "art",  "kind": "artwork",    "elements": [] },
    { "id": "silk", "kind": "silkscreen", "elements": [ /* text/shape */ ] },
    { "id": "knob", "kind": "knobs", "elements": [
      { "id": "k1", "asset": "builtin/knob-skb", "param": "gain",
        "anchor": [52.0, 20.0], "anchor_mode": "top-center",
        "radius": 9.5, "pointer_len": 8.0, "pointer_width": 0.8,
        "angle_min": -135.0, "angle_max": 135.0, "drag_full_range_mm": 60.0 }
    ]},
    { "id": "sw",   "kind": "toggles", "elements": [
      { "id": "t1", "param": "symmetric", "x": 22.0,
        "y_up": 30.0, "y_down": 30.4, "w": 8.0, "h": 8.5,
        "pivot": [26.0, 34.5], "press_scale": 0.9,
        "asset_up": "assets/switch_up.png", "asset_down": "assets/switch_down.png" }
    ]},
    { "id": "led",  "kind": "leds", "elements": [
      { "id": "l1", "param": "clip_indicator", "center": [52.0, 8.0], "radius": 2.5,
        "off": "#a00000", "on": "#ff0000" }
    ]}
  ]
}
```

### 3.3 导出产物

| 产物 | 内容 |
|---|---|
| `assets/panel@2x.png` | 背景 + 装饰 + 丝印 + 旋钮本体 + 拨杆底座 + 按钮美术（**压平**） |
| `assets/switch_up@4x.png` / `switch_down@4x.png` | 拨杆活动部分（两态，alpha） |
| `rustomp.toml` 的 `[assets]` + `[ui]` | 标记块内替换 |
| （可选）`panel-1to1.pdf` | 1:1 打印（不参与插件构建） |

## 4. 建议同步给 rustomp 的扩展（不阻塞设计器）

| # | 扩展 | 理由 |
|---|---|---|
| 1 | `led/toggle/button` 从 `Option<T>` 改成 `&'static [T]` | 真实面板常有 2 个拨杆/多个指示灯 |
| 2 | 旋钮指针颜色/宽度可配置（放进 `KnobSpec`） | 深色面板上白针会看不见 |
| 3 | 拨杆支持**多态**（>2 态，如三档开关） | 旋转开关/档位选择 |
| 4 | 文字元素（可选，后期） | 若希望参数名随语言切换，而不是永远压平 |
