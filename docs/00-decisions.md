## D0 的范围（2026-10-26 拍板）

**D0 只做四种控件：旋钮 + 拨杆 + LED + 脚踏（button）。**

| 不做 | 原因 |
|---|---|
| 多位开关（旋转开关 / 3 档以上） | **走"开关逻辑"**：开关 = 两份（或多份）完整电路，由插件层 `Branch<A,B>` 交叉淡化（rustomp D-005）。面板上它就是一个普通拨杆，不需要新的控件类型 |
| 数值显示 / 表头指针 | 未来可能加，**D0 不做** |
| 文字随语言切换 | 丝印一律栅格化进底图（D-002） |

## D-001 技术栈：零依赖的浏览器原生 ES modules + 原生 SVG

**结论**：前端是纯 HTML + ES modules + 原生 SVG，**不装任何 npm 包**（无 Vite/框架）；
本地开发用 `python3 -m http.server` 起静态服务。导出走 Node 脚本（`scripts/export.mjs`）+ Inkscape 栅格化。

**理由**

1. D0 不需要后端：布局、绘制、导出全是纯函数，没有求解/网络；
2. 素材全是 SVG，浏览器原生就能画；**不用引图形库**；
3. 这台机器（Hackintosh）对大量 IO 敏感，`npm install` 拉几百个包是没必要的风险；
4. 代码按 ES module 分文件，将来要上 Vite/TS 是"加一层"而不是重写。

**影响**：没有类型检查（用 node 的测试兜住纯逻辑）；预览与导出**共用同一份 SVG 生成代码**，保证所见即所得。

## D-002 设计文件：`.box.json` 是唯一事实来源，导出是单向的

**结论**：设计器读写 `.box.json`（`version: 1`），导出 `rustomp.toml` 的两个标记块
（`# >>> rustomp-box-designer` … `# <<<`）。同一个 `.box.json` 必须导出逐字节相同的文本（幂等，可做漂移检查）。

**理由**：设计稿要能 diff、能版本化；`rustomp.toml` 的 `[plugin]/[au]/[[params]]` 由插件作者维护，设计器不许碰。

## D-003 图层：7 层，按"它最后去哪"划分

```text
box.json.layers[]（顺序 = 自下而上）
  background   背景（面板底板、底色）        → 压平进 panel.png
  artwork      装饰（螺丝、贴纸、做旧）      → 压平
  silkscreen   丝印（文字/刻度/logo）        → 压平（**文字一律栅格化**）
  knobs        旋钮                          → 本体压平；运行时整图旋转（指针朝上 = 0.5）
  toggles      拨杆                          → 活动部分导出两态 PNG；底座压平
  leds         LED                           → 底座压平；点亮由运行时画
  buttons      脚踏（3PDT 等）               → 美术压平；按下时运行时从底图抠出缩放
```

**理由**：划分依据不是"图形类型"而是"导出时去哪"——这样运行时不需要理解设计稿。

## D-004 控件数量：数组，不限个数

**结论**：`PanelSpec` 的 `knobs/toggles/leds/buttons` 全是 `&'static [T]`（框架已在 rustomp E60 完成）。
设计器按数组建模，导出时校验"引用的参数存在、素材存在、控件不越界"。

## D-005 坐标：1 单位 = 1 毫米，吸附 0.5 mm

**结论**：`box.json` 与 `rustomp.toml [ui]` 的单位都是 **mm**，`y` 向下。
编辑时吸附 0.5 mm（可用 `Alt` 临时关闭），导出保留 0.01 mm。

**理由**：运行时本来就用 mm（`svg_width × 6 px/mm` = 逻辑窗口）；导出素材是 `mm × 12 px/mm`。
用像素编辑会在 HiDPI 下算错（rustomp DEVLOG E61 的教训）。

---

## D-006 素材：外部 SVG 内联时必须"扁平化"

**结论**：素材 SVG 是 `pt` 坐标 + `viewBox` + `<defs><style>` 类名。内联进面板 SVG 时：

1. 用**嵌套 `<svg x y width height viewBox>`**（不是 `<g transform>`）——素材的 path 坐标常常远在
   viewBox 之外（如 label 的 `M253,393`），只有嵌套 viewport 才能正确裁剪；
2. 把 `class="cls-N"` 的样式**展开成内联 `style`**，并删掉 `<defs><style>` —— 否则多个素材的
   `.cls-1` 会互相覆盖；
3. 删掉所有 `id`（多个素材会有同名 `layer1`）。

**像素密度**：面板与控件贴图一律 **12 px/mm**（= 304.8 dpi）。

## D-009 参数来源：读插件项目的 `rustomp.toml`

**结论**：设计器加载 `[[params]]` 的 id/name/type，控件下拉里只能选这些 id；
绑定到不存在的参数时 inspector 标红、导出报错。

**理由**：参数表由插件作者维护，设计器只读——两份清单必然漂移。

## D-010 D1 编辑增强（2026-10-26）

| 能力 | 约定 |
|---|---|
| 安全边距 | 画布内缩 4 mm 的参考线（**只提示，不限制**），数值在 `view.safe_margin_mm` |
| 吸附 | 两段式：先按 `view.snap_mm`（默认 0.5 mm）吸附，再吸附到**画布中线/边 + 其它控件的边/中线**（阈值 1.2 mm）；命中时画蓝线；`Alt` 全程关闭吸附 |
| 图层 | 7 层，每层可**隐藏**（不渲染、不可选）与**锁定**（可渲染、不可选/不可拖）；状态存在 `box.json.layers`，不影响导出 |
| 撤销/重做 | `⌘Z` / `⇧⌘Z`（`Ctrl+Z`/`Ctrl+Y`），一次拖动只记一步；栈深 60 |
| 脚踏按住态 | 素材若存在 `<id>_hold.svg`，自动配对成 `image_hold`；导出 `[assets]` 里多一张 PNG，`[[ui.buttons]]` 多 `image_hold`/`image_size` |

> 素材命名规则统一：文件名里的 `-` 一律规范成 `_`（Rust 贴图名习惯），
> 例如 `3pdt_alt-hold.svg` → id `3pdt_alt_hold`。

### D-010.1 拨杆两态：按**六边形中心**对齐，不是按贴图顶边（2026-10-26）

拨杆素材是**镜像画的**：上半的六边形偏下（y 中心 4.72 mm）、下半的偏上（4.18 mm）。
两态贴同一个 y，六边形中心就差 **0.54 mm（小）/ 0.95 mm（大）** —— 这就是 legacy 版
"切换时基线跳 1.53 pt"的老毛病。

约定：

1. `gen-assets.mjs` 从 `polyline/polygon` 的点算出**六边形包围盒中心**，写进清单 `hex_center_mm`；
2. `factory.toggle` 让 `y_down = y_up + (up.hex_y − down.hex_y)`，并令 **`pivot` = 六边形中心**（按下缩放的原点）；
3. 校验判据改成「两态六边形中心的绝对 y 相差 < 0.02 mm」，**不再要求 y_up == y_down**；
4. 横向若两态不一致（`hex_x` 不同）直接报错 —— 单个 `x` 字段表达不了横向补偿，只能换素材。

### D-010.2 旁通预览（2026-10-26）

预览里点脚踏 = **切换旁通**（与真插件一致：点按切换，不是按住），按下期间显示按住态贴图，
抬起后 LED 变灰且不再闪（色值与 `rustomp-gui::led_grey` 同一公式，`greyColor()`）。

| 能力 | 说明 |

## D-011 图层用「焦点」而不是「锁定」管理（2026-10-26）

**结论**：删掉锁定（`locked`），改成**焦点图层**。

| 行为 | 说明 |
|---|---|
| 进入焦点 | 点图层行（或名字）→ 该图层成为焦点；再点一次退出（回到"全部可编辑"） |
| 焦点时的画布 | **焦点图层正常显示**；其它图层整体 `opacity 0.28` 虚化（位置仍可见），**不可选中/不可拖动** |
| 焦点时的素材库 | 不属于焦点图层的素材**变灰 + 不可点**（`pointer-events: none`） |
| 新加的元素 | 若不在当前焦点图层，**自动把焦点切过去**（否则"加了却拖不动"，很迷惑） |
| 显隐 | 保留（眼睛按钮），与焦点正交：隐藏是"不参与渲染/导出"，焦点是"不可编辑" |

**理由**：锁定解决不了"我到底在改哪一层"，反而让人忘了自己锁过什么；
焦点把"当前工作对象"变成一个显式、可见、可一键退出的状态，符合"一次只调一层"的实际工作流。

> 焦点是编辑器的**会话状态**（`state.focus`），不写进 `box.json`。
