## D0 的范围（2026-10-26 拍板）

**D0 只做四种控件：旋钮 + 拨杆 + LED + 脚踏（button）。**

| 不做 | 原因 |
|---|---|
| 多位开关（旋转开关 / 3 档以上） | **走"开关逻辑"**：开关 = 两份（或多份）完整电路，由插件层 `Branch<A,B>` 交叉淡化（rustomp D-005）。面板上它就是一个普通拨杆，不需要新的控件类型 |
| 数值显示 / 表头指针 | 未来可能加，**D0 不做** |
| 文字随语言切换 | 丝印一律栅格化进底图（D-002） |

## D-001 技术栈：零依赖的浏览器原生 ES modules + 原生 SVG

**结论**：前端是纯 HTML + ES modules + 原生 SVG，**不装任何 npm 包**（无 Vite/框架）；
本地开发用 `scripts/dev.sh`（Python 标准库：静态文件 + 可选的暂存 API）起服务。导出走 Node 脚本（`scripts/export.mjs`）+ Inkscape 栅格化。

**理由**

1. D0 不需要后端：布局、绘制、导出全是纯函数，没有求解/网络；
2. 素材全是 SVG，浏览器原生就能画；**不用引图形库**；
3. 这台机器（Hackintosh）对大量 IO 敏感，`npm install` 拉几百个包是没必要的风险；
4. 代码按 ES module 分文件，将来要上 Vite/TS 是"加一层"而不是重写。

**影响**：没有类型检查（用 node 的测试兜住纯逻辑）；预览与导出**共用同一份 SVG 生成代码**，保证所见即所得。

---

## D-002 设计文件：`.box.json` 是唯一事实来源，导出是单向的

**结论**：设计器读写 `.box.json`（`version: 1`），导出 `rustomp.toml` 的两个标记块
（`# >>> rustomp-box-designer` … `# <<<`）。同一个 `.box.json` 必须导出逐字节相同的文本（幂等，可做漂移检查）。

**理由**：设计稿要能 diff、能版本化；`rustomp.toml` 的 `[plugin]/[au]/[[params]]` 由插件作者维护，设计器不许碰。

## D-003 图层：7 层，按"它最后去哪"划分

```text
box.json.layers[]（顺序 = 自下而上）
  background   背景（面板底板、底色）        → 压平进 panel.png
  artwork      装饰（螺丝、贴纸、做旧）      → 压平
  silkscreen   丝印（文字/刻度/logo）        → 压平（**文字一律栅格化**）
  knobs        旋钮                          → 本体压平；运行时整图旋转（指针朝上 = 0.5）
  toggles      拨杆                          → 活动部分导出两态 PNG；底座压平
  leds         LED                           → 底座压平；点亮由运行时画
  buttons      脚踏（3PDT 等）               → 美术压平；按下时运行时从底图抠出缩放
```

**理由**：划分依据不是"图形类型"而是"导出时去哪"——这样运行时不需要理解设计稿。

## D-004 控件数量：数组，不限个数

**结论**：`PanelSpec` 的 `knobs/toggles/leds/buttons` 全是 `&'static [T]`（框架已在 rustomp E60 完成）。
设计器按数组建模，导出时校验"引用的参数存在、素材存在、控件不越界"。

## D-005 坐标：1 单位 = 1 毫米，吸附 0.5 mm

**结论**：`box.json` 与 `rustomp.toml [ui]` 的单位都是 **mm**，`y` 向下。
编辑时吸附 0.5 mm（可用 `Alt` 临时关闭），导出保留 0.01 mm。

**理由**：运行时本来就用 mm（`svg_width × 6 px/mm` = 逻辑窗口）；导出素材是 `mm × 12 px/mm`。
用像素编辑会在 HiDPI 下算错（rustomp DEVLOG E61 的教训）。

---

## D-006 素材：外部 SVG 内联时必须"扁平化"

**结论**：素材 SVG 是 `pt` 坐标 + `viewBox` + `<defs><style>` 类名。内联进面板 SVG 时：

1. 用**嵌套 `<svg x y width height viewBox>`**（不是 `<g transform>`）——素材的 path 坐标常常远在
   viewBox 之外（如 label 的 `M253,393`），只有嵌套 viewport 才能正确裁剪；
2. 把 `class="cls-N"` 的样式**展开成内联 `style`**，并删掉 `<defs><style>` —— 否则多个素材的
   `.cls-1` 会互相覆盖；
3. 删掉所有 `id`（多个素材会有同名 `layer1`）。

**像素密度**：面板与控件贴图一律 **12 px/mm**（= 304.8 dpi）。

### D-010.1 拨杆两态：按**六边形中心**对齐，不是按贴图顶边（2026-10-26）

拨杆素材是**镜像画的**：上半的六边形偏下（y 中心 4.72 mm）、下半的偏上（4.18 mm）。
两态贴同一个 y，六边形中心就差 **0.54 mm（小）/ 0.95 mm（大）** —— 这就是 legacy 版
"切换时基线跳 1.53 pt"的老毛病。

约定：

1. `gen-assets.mjs` 从 `polyline/polygon` 的点算出**六边形包围盒中心**，写进清单 `hex_center_mm`；
2. `factory.toggle` 让 `y_down = y_up + (up.hex_y − down.hex_y)`，并令 **`pivot` = 六边形中心**（按下缩放的原点）；
3. 校验判据改成「两态六边形中心的绝对 y 相差 < 0.02 mm」，**不再要求 y_up == y_down**；
4. 横向若两态不一致（`hex_x` 不同）直接报错 —— 单个 `x` 字段表达不了横向补偿，只能换素材。

### D-010.2 旁通预览（2026-10-26）

预览里点脚踏 = **切换旁通**（与真插件一致：点按切换，不是按住），按下期间显示按住态贴图，
抬起后 LED 变灰且不再闪（色值与 `rustomp-gui::led_grey` 同一公式，`greyColor()`）。

### D-010.3 D1.5：多选与对齐（2026-10-26）

| 能力 | 说明 |
|---|---|
| 多选 | `Shift`/`⌘` 点选加入或移除；多选时画联合外接框 |

## D-011 图层用「焦点」而不是「锁定」管理（2026-10-26）

**结论**：删掉锁定（`locked`），改成**焦点图层**。

| 行为 | 说明 |
|---|---|
| 进入焦点 | 点图层行（或名字）→ 该图层成为焦点；再点一次退出（回到"全部可编辑"） |
| 焦点时的画布 | **焦点图层正常显示**；其它图层整体 `opacity 0.28` 虚化（位置仍可见），**不可选中/不可拖动** |
| 焦点时的素材库 | 不属于焦点图层的素材**变灰 + 不可点**（`pointer-events: none`） |
| 新加的元素 | 若不在当前焦点图层，**自动把焦点切过去**（否则"加了却拖不动"，很迷惑） |
| 显隐 | 保留（眼睛按钮），与焦点正交：隐藏是"不参与渲染/导出"，焦点是"不可编辑" |

**理由**：锁定解决不了"我到底在改哪一层"，反而让人忘了自己锁过什么；
焦点把"当前工作对象"变成一个显式、可见、可一键退出的状态，符合"一次只调一层"的实际工作流。

> 焦点是编辑器的**会话状态**（`state.focus`），不写进 `box.json`。

## D-012 编辑交互修订（2026-10-26，按用户实测反馈）

| # | 决定 | 理由 |
|---|---|---|
| 1 | **没有焦点 = 全部虚化且不可交互** | 焦点是"现在改哪一层"的唯一入口；不设默认焦点，避免"以为在改 A 层其实动了 B 层" |
| 2 | **禁用拖动**（`pointerdown` 只做选中） | 拖动手感不可控（栅格 `0.5 mm` + 吸附 + 高频重渲染），不如方向键与数值输入可靠 |
| 3 | **双击素材库新建**，新元素一律落在**画布中心** | 单击容易被误触；中心落点让新元素一定在视野内 |
| 4 | 属性面板**坐标向下取整**（`Math.floor`） | 做面板时整数毫米更好对位；尺寸/角度保留小数 |
| 5 | 属性面板的 `input` 监听**启动时挂一次**（去掉 `{once:true}`） | 原来的 `{once:true}` + 不重绘面板 = **第一次输入后整个面板就死了** |
| 6 | 撤销：`focusin` 时记一步 | 不再"每敲一个字一步撤销" |

**移动元素的三条路**（拖动退役后）：

1. 方向键 `0.1 mm`，`Shift+方向键` `1 mm`（多选一起动）；
2. 右侧属性面板输入精确值（坐标取整）；
3. 「对齐」按钮（多选时对选区/对画布）。

> 说明：`w/h/rx/radius/travel_deg/rot/press_scale` 仍保留小数精度，
> 取整只作用于**位置**（`x/y/y_up/center/pivot`）。

## D-013 旋钮尺寸随素材 / 装饰层边框 / 导入外部 SVG（2026-10-26，按用户反馈）

### 13.1 旋钮不再暴露"半径"

尺寸由素材决定：`image_size = 素材 size_mm`，**命中半径 = 贴图宽/2**（导出时算）。
属性面板只显示一行只读尺寸，不再有半径输入框 —— 改了只会让点击区和美术对不上。

> 旧 `.box.json` 里的 `image_size` / `radius` 在 `load()` 时**自动按素材刷新**，
> 所以用户改了 `knob_round_dark.svg` 的尺寸，打开旧文件也立刻跟上。

### 13.2 装饰层新增 `frame`（面板边框）

以前新建文档里是个裸 `rect`：既选不中（导出时没打 `data-elid`），又要手工跟着画布改尺寸。

现在是一个**专门的元素类型**：

```jsonc
{ "kind": "frame", "layer": "artwork", "margin": 1.2, "rx": 2.2, "strokeWidth": 0.35, "stroke": "#231815" }
```

- 几何**由画布推算**（`x = margin`，`w = 画布宽 − 2·margin`），改画布自动跟随；
- 只暴露"内缩 / 圆角 / 线宽 / 颜色"四个参数；
- 不可移动（挪它没有意义），新建文档自动带一个；
- 导出时压平进 `panel.png`（不进 `[ui]`）。

顺带修了 `rect` 也选不中的问题（导出时加回 `data-elid`）。

### 13.3 导入外部 SVG（只允许装饰 / 丝印）

| 规则 | 说明 |
|---|---|
| 类必须手选 | 导入弹窗里选「装饰 artwork」或「丝印 silkscreen」，**不允许导入成控件** |
| 自包含 | SVG 文本存进 `.box.json` 的 `imported[]`，设计文件不依赖外部文件 |
| 出现位置 | 左侧素材库对应分组（`装饰（导入）` / `丝印（导入）`），双击使用 |
| 尺寸 | 从 `viewBox` 读（pt→mm），没有 viewBox 时退用 `width/height`，都读不出就报错 |
| 为什么只允许这两层 | 它们最终**压平进 panel.png**，不需要额外的运行时贴图；控件层要两态贴图/旋转语义，得走内置素材 |

导入素材在导出时与内置素材一样参与内联（`mergedAssets()`），所以 CLI 也能渲染。

## D-014 控件尺寸一律随素材 / 参数绑定按类型过滤（2026-10-26）

### 14.1 控件尺寸不再可调

| 控件 | 尺寸来源 | 面板里显示 |
|---|---|---|
| 旋钮 | 素材 `size_mm`；命中半径 = 宽/2 | 只读一行尺寸 |
| LED | 素材 **内圈（镜片）半径** | 只读一行半径 |
| 脚踏 | 素材宽/2（必须盖住美术，按下要擦掉这块）；按住态**整张换图**，所以"按下缩放"无意义 | 只读一行半径 |

导出时由 `ledRadius()` / `buttonRadius()` 算出写进 `[ui]`，
旧 `.box.json` 里的 `radius` / `press_scale` 一律忽略（`load()` 时删掉旋钮的 `radius`）。

### 14.2 参数绑定必须类型匹配

```js
ALLOWED_PARAM_KIND = { knob: "float", toggle: "bool", button: "bool", led: "indicator" }
```

- 属性面板的下拉**只列出类型匹配的参数**（`paramChoices()`）；
  历史错配的当前值仍会显示，但标 `⚠ 类型不匹配`，方便发现和改掉；
- `validate()` 会报错：`knob 只能绑 float 类型参数，"bypass" 不是`；
- 新建元素时默认参数也按类型挑（旋钮→第一个 float，拨杆/脚踏→第一个 bool，LED→`clip_indicator`）。

**为什么要这么严**：错配不会让插件崩，只会表现成"拖了没反应"（旋钮绑 bool）或
"灯永远亮"（LED 绑 float 参数）—— 是最难查的一类问题。

### 14.3 导入外部 SVG 的崩溃（`size_mm` of undefined）

根因：`addElement()` 里贴图分支只查内置清单 `byId(id)`，而导入素材的 id 是 `imp_*`，
不在内置清单里 → `undefined.size_mm` 崩掉。

修法：统一走 `assetInfo(doc, id)`（内置清单 + `doc.imported[]` 两处查），
并把添加流程包一层 `try/catch`，出错时在状态栏给出人话提示而不是抛到控制台。

## D-015 一键素材包 / 坐标改浮点 / 旋钮行程写死（2026-10-27）

### 15.1 导出弹窗新增「下载素材包（zip）」

以前导出只给两个文件（`ui.toml` + `panel.svg`），`[assets]` 点名的 4 张 PNG 得自己栅格化 —— 交接时必然缺件。
现在一键下载 **11 个文件**：

| 文件 | 来源 |
|---|---|
| `panel.svg` | 面板矢量（自包含） |
| `panel.png` | 浏览器 canvas 栅格化，`mm × 12 px/mm` |
| `<knob>.png`、`<toggle>_up/down.png`、`<footswitch>_hold.png` | 各素材的原尺寸贴图 |
| `ui.toml` | `[assets]` + `[ui]` 标记块 |
| `panel.box.json` | 设计文件本身（可回设计器继续改） |

实现要点：

- **zip 自己写**（`src/zip.js`，store 不压缩，100 行）：设计器坚持零依赖，PNG 本来也压不动；
- **栅格化用 canvas**（`src/raster.js`）：重写 SVG 的 `width/height` 为目标像素、保留 `viewBox`，再 `drawImage`；
- 文件名**不允许空格**（各家解压器行为不一致）；
- 浏览器产物与 CLI（Inkscape）**像素尺寸完全一致**，差异只在抗锯齿的极小细节；
  **CI/权威产物仍走 CLI**，浏览器那份是"拿来就能用"的便利路径。

### 15.2 坐标改为浮点毫米

"整数毫米取整"当初是为**拖放栅格**服务的；拖动已禁用（D-012），这个约束就没有意义了，
还会让"我想放 12.35 mm"变得不可能。

- 属性面板里 `x / y / y_up / center[pivot] / w / h` 一律接受小数，**输入多少就是多少**；
- 新元素落在画布正中（60×112 → `30 / 56`，奇数尺寸自然得到 `.5`）；
- 方向键仍是 0.1 mm / `Shift` 1 mm 的浮点步进。

### 15.3 旋钮行程写死 270°

`travel_deg` 从模型与面板里删掉，导出恒为 270°（`KNOB_TRAVEL_DEG`）。

理由：**「指针朝上 ⇔ 参数 0.5」这个契约本身就要求对称行程**（`angle_min + angle_max == 0`），
可调等于给用户一个能把契约弄坏的旋钮。要改行程就是改框架契约，不是改某个面板。

## D-016 浏览器 zip 与 CLI 的分工 / 导入素材必须两条路都支持（2026-10-27）

### 16.1 CLI 侧不认 `imported[]`（已修）

`scripts/export.mjs` / `preview.mjs` 之前只从 `assets.gen.js` 加载内置素材，
遇到设计稿里的外部导入（`box.json.imported[]`）就崩：`素材缺少 viewBox` / `素材文件读不到：imp_*`。

修法：

- `export.mjs`：`readAssets()` 只负责内置素材，"缺件"判断要**排除 imported 的 id**，
  最后统一走 `mergedAssets(doc, builtin)`；
- `preview.mjs`：同样用 `mergedAssets()`。

### 16.2 浏览器 PNG 与 Inkscape PNG 的关系（明确下来）

| | 生成方式 | 用途 |
|---|---|---|
| 浏览器 zip 里的 PNG | canvas `drawImage` | 交付给人用（下载即用） |
| CLI 的 PNG | Inkscape | **权威产物**，CI / 逐字节可复现 |

两者**像素尺寸完全一致**（mm × 12），但**字节不同**（抗锯齿实现不同）。
所以：不要拿浏览器产物做逐字节对比；要可复现就走 CLI。

### 16.3 一次"美术改动"的交接长什么样

用户这次只改了美术（加了 3 个导入素材、删了 CLIP 标签、移动了标签位置），没动控件，于是：

```text
panel.png   变了（底图含新 logo）
[ui]        完全没变  →  rustomp-gen 报告 "已写入 0 个文件（7 个未变）"
```

这条经验值得记住：**美术改动只动 `panel.png`，控件改动只动 `[ui]`** —— 两者互不牵连，
所以"重新导出一次"不会顺手把别人的布局改动踩掉。

## D-017 暂存到服务端：只做本地开发态，不改变导出链路（2026-10-29）

**结论**：顶栏新增「暂存」按钮，把当前 `.box.json` 写到本地开发服务的缓存；
启动时自动恢复上次暂存。语义对齐 `rustomp-circuit-designer` 的 `designer.save/last`。

| 项 | 内容 |
|---|---|
| API | `POST /api/draft { name, doc }` → `<repo>/.cache/designs/<name>.box.json` + `last` 指针；`GET /api/draft` 读回 |
| 服务 | `scripts/server.py`（Python 标准库，随 `./scripts/dev.sh` 启动；无 npm/Rust 依赖） |
| 前端 | `src/backend.js`：`draft.save()` / `draft.last()`；失败只在状态栏提示 |
| 自动恢复 | 启动时读 `last`；`?demo=1` / `?selftest=1` / `?fresh=1` 不恢复 |
| 保存语义 | 写一份，并**清空撤销/重做**（与 circuit-designer、breadspice 一致） |
| 缓存目录 | 默认 `.cache/designs`（已 gitignore），`BOXD_DATA` 可覆盖 |
| 安全/健壮 | 名字清洗路径分隔符与危险字符；原子写；请求体上限 8 MB；`/.cache` 不经静态服务暴露 |

**为什么不做成 Rust 后端**：本仓的 D-001 是"零依赖、无构建"；暂存只是把 JSON 写到本地，
用 Python 标准库足够。导出/预览仍是纯前端 + Node CLI，不受影响。

**边界**：静态托管（GitHub Pages 等）没有这个 API，按钮会提示"暂存失败（用 ./scripts/dev.sh）"；
草稿不做版本迁移/冲突合并，只是"上次一份"。
